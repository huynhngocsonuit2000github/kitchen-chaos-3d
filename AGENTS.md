# Codex operating contract — v1.1
Read studio/AI_GAME_STUDIO_SKILLS.md; docs/GDD.md, ART_DIRECTION.md, VISUAL_TARGETS.md, CHARACTER_BIBLE.md, LEVEL_BLUEPRINT.md, INTERACTIONS_AND_ANIMATION.md, UI_DESIGN.md, TECH_DESIGN.md, AUDIO_PLAN.md, ASSET_PIPELINE.md, CONTENT_PIPELINE.md, LIVE_PREVIEW.md; production files and QA report. GDD/approved decisions are authoritative for mechanics; concept images only visual reference. If conflict, record and resolve against decisions; ask Producer only for material scope/approval conflict. Inspect repository and current progress before editing. Preserve existing features and unrelated changes.

Execute milestone batches, not single-ticket turns: select all dependency-ready related tasks in the current authorized milestone; implement, integrate, run checks, fix and continue to next ready task within same milestone. Start with M0-01 + M0-02 + M0-03 as dependencies clear; stop at G0 for Producer approval. Later run M1 as a complete batch through G1. G1 is evidence gate, not mandatory human pause; if G0 authorized M2 as well, advance only after G1 passes, otherwise report and request next milestone. G2 and G4 always human approval; G3 evidence gate. Do not scale worlds before G2. No merging, deployment, repo visibility change, paid service, online multiplayer or external AI runtime without authorization. Never silently bypass asset blockers: continue independent tasks in authorized scope, record blocked IDs and required input, stop when critical path blocked. Three attempts per repeated failure unless new evidence; no endless retry. Stop on context/resource exhaustion with durable checkpoint, no pretend continuation.

Use strict TypeScript, deterministic simulation, accessible UI, data-driven content. Run npm ci (once lockfile exists), typecheck, lint, test, build, e2e when configured; actual gameplay evidence required. Record commands, exit codes, commit, screenshot paths, defects and next tasks in PROGRESS.md and QA_REPORT.md, update BACKLOG statuses. Record PASS/FAIL/BLOCKED/NOT_RUN per test. No invented outputs. Keep PR milestone-sized and prepare review summary. Use concept crops for comparison but no concept as runtime model. Only labeled M1 graybox temporary assets; no unapproved placeholders in G2/release. Verify actual runtime files, rights, scale, animation and visual match. Use templates under templates/github-actions only after adapting and validating; publication separately authorized. Never expose credentials. Studio generic single-slice wording is refined here to permit milestone-sized batches with same safety and quality gates.

The Producer authorizes automatic GitHub Pages preview deployment from `main`. Treat a merge to `main` as preview publication once the Pages workflow passes typecheck, lint, unit tests, build and Chromium checks. PR checks do not deploy. Keep the existing Pages URL and base path. Manual recovery reruns the verified workflow from `main` or uses a reviewed revert PR. Follow [LIVE_PREVIEW.md](docs/LIVE_PREVIEW.md). Milestone quality gates and final release approval remain mandatory.
