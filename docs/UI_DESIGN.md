# UI design specification
Visual reference assets/concept/05_ui.png; not a pixel-perfect implementation. Original SVG icons and rounded cream panels, teal selection, tomato warnings, warm shadows. System rounded sans fallback until licensed font approved. DOM overlay, accessible names and keyboard focus; 1280x720 baseline, scale to 1920x1080. Minimum text 16px HUD / 14px labels; buttons >=40px. Contrast target WCAG AA for text; icon+text for status. No hover-only actions.
## Screens and states
- Boot: loading progress, retry/error details, version. Menu: Continue/New Career, Settings, optional modes locked with explanation. Confirm destructive reset.
- Planning: top day/cash/reputation; left category tabs Equipment/Menu/Staff; center live grid; right selected item cost and effect; bottom confirm/cancel/undo/start shift. Invalid ghost red+blocked label. Show cash after purchase before confirm; insufficient funds disabled with reason. Menu locks by day.
- Service: top horizontal order cards (icon + ingredient icons + patience bar, numeric remaining seconds optional), center timer and served/target; lower left active chef portrait/action prompt/held item; lower right cash/tip; station-local ready/burn icons + global warning. Top queue compact first 3 with Tab expansion, never covers essential station. No illustrated fries in slice.
- Results: served/target, misses, waste, sales, tips, ingredient cost, wages, overhead, net, reputation delta; Next Day / Retry / Management. Retry semantics must not double-settle: restore pre-shift snapshot only if uncommitted; after settlement repeat as new day.
- Settings: master/music/SFX, low graphics, reduced motion, controls; pause/resume and restart confirmation. Focus loss pauses; Tab order expansion in active gameplay only, regular keyboard focus in menus.
## Acceptance
Q11 screenshot at both resolutions; keyboard navigation without mouse in menus, visible focus and no trap, labels for buttons and warnings, no clipping at 100% browser zoom, reduced motion suppresses shake/excess particles. Q17 verifies exact money and order display match simulation; Q18 tests invalid purchase and cancel; use test IDs and DOM assertions, visual screenshot review separate.
