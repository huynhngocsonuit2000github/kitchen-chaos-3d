# Technical design
Proposed stack: TypeScript strict, Vite, Three.js, Vitest, Playwright, Howler.js optional; Rapier only if collision needs exceed grid/AABB solution. Static hosting, no backend, LLM, multiplayer or paid service. Pin compatible versions and Node LTS at implementation after checking actual environment; commit lockfile. 
## Architecture
src/game/simulation (fixed 60 Hz tick, seeded RNG, pure state transitions), input (action mapping, focus reset), world (grid/layout/pathfinding), systems (orders, cooking, inventory, staff, economy), rendering (Three.js scene, animation, interpolation), ui (DOM overlay), audio, assets, persistence. One authoritative simulation state; render/audio/UI consume events or snapshots, never mutate rules directly. State phases Boot→Menu→Planning→Service→Results→Planning; Pause overlays Service; Error/retry for failed assets. Simulation time only advances in active service. Clamp accumulated delta and cap catch-up ticks. Test hooks allow deterministic input and clock. 
Entities: stable IDs; item recipe/state/container/owner; station capacity/reservation/timer; chef position/held item/task; order recipe/modifiers/patience/status; restaurant grid/equipment/stock/cash/reputation/day. Transfers atomic: validate destination then remove source and add target; invariant each item has exactly one owner. Staff task queue with reservation, pathfinding and cancellation on blocked route; manual takeover releases reservation. Grid validation flood fill from chef spawn to required stations and exit. Recipe and tuning JSON validated on startup. 
Persistence: versioned localStorage career snapshot, validation and migration, backup previous valid save; corrupt data prompts restore/reset rather than crashing. Save only at management transactions and settlement, idempotent day settlement; separate challenge/sandbox data. Export/import JSON optional after slice. No personal data. Pause on visibility loss; user resumes explicitly. 
## Performance targets (unverified)
Desktop Chrome/Edge/Firefox; 1280x720 minimum; medium desktop baseline to be recorded by Producer. 60 FPS target (16.7ms frame), fallback low settings 30 FPS; initial transfer ≤20 MB, first slice ≤50 MB, long-term total 100–200 MB streamed by scene. Provisional visible triangles ≤180k, draw calls ≤150, texture GPU memory ≤128 MB, ≤12 animated characters, ≤250 active particles. Chef 5–12k triangles, hero food 1–3k, props 0.3–3k; textures 512–1024 mostly, shared atlases. Measure actual device and report p95 frame time, network transfer and memory when supported. Use instancing, material reuse, shadow budget, capped pixel ratio, lazy loading, dispose scene resources. No unsupported performance claims.
## CI/deployment
npm ci; npm run typecheck; npm run lint; npm test; npm run build; npm run test:e2e (define scripts in M0). GitHub Actions PR checks, dist artifact, optional GitHub Pages after approval; configure base path and verify asset URLs/MIME. Browser smoke on deployed URL; no public deployment until privacy/rights approved. Record commit and rollback release. No credentials in code.
